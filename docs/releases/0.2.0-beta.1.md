# TokenFish 0.2.0-beta.1 candidate

## Changes

- Keep Codex and Claude, with shared fish/pellet quota rails, prominent remaining percentages, named quota groups, exact reset tooltips, and freshness feedback.
- Restore the fish's token-eating mouth animation in the full view and widget. Fish positions still reflect consumed quota. Motion pauses when hidden or unloaded and respects Windows' animation preference.
- Add an optional corner widget, show/hide controls, optional always-on-top, dragging with corner snapping, keyboard corner selection, and saved corner/monitor anchors. Click usage to open the full view.
- Place Settings beside its invoking widget or popup, clamped to the same monitor. Reposition reused Settings windows for each invocation.
- Add Connections, Desktop, and Appearance settings. System, Light, and Dark appearance apply immediately. Connection changes in Settings still require restart.
- Correct saved runtime and distribution controls, provider-specific setup progress, both Windows/WSL Claude snippets, and edited setup reverification. Ignore obsolete verification results after going back.
- Add 15-second Codex startup, 20-second collection, and 5-second optional activity deadlines. Discard failed sessions and reconnect on a later refresh. Preserve usable quota when optional activity fails; unsupported activity does not require reconnecting.
- Show Claude weekly quota when reported. Preserve Codex bucket names. Show dated activity with explicit UTC coverage and missing-day markers; optional lifetime, peak, streak, and longest-turn values appear only when reported.
- Reapply borderless native styling after activation/placement, remove extended native edge flags, and disable DWM non-client rendering for the fully drawn popup/widget surfaces. A window-specific WM_NCCALCSIZE hook lets content fill the entire native window; earlier style-only fixes still left a visible rim. This follows [Microsoft's client-area calculation guidance](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-nccalcsize).
- Add a versioned portable ZIP/checksum script, SDK selection, user documentation, and Windows GitHub Actions build artifacts.

## Automated validation

The x64 Debug solution build passed with **zero warnings/errors**. **825 tests passed**, with zero failures or skips: Core 100, Infrastructure 408, Codex 247, Claude 70. This adds 42 focused cases to the 783-test audit baseline, including animation eligibility for reduced motion, hidden windows, and unloaded rails.

Coverage includes adjacent placement at all corners and negative coordinates, narrow work areas and DPI sizing, widget corner persistence and placement, legacy settings compatibility, setup routes and runtime replacement, stalled process deadlines, reconnection, independent optional activity failure, and optional summary fields. Existing tray, refresh, privacy, and Claude tests still pass.

The self-contained x64 Release publish succeeds with the two known SDK/runtime IL2104 trimming warnings for Microsoft.Windows.SDK.NET and WinRT.Runtime. No TokenFish application build warnings were observed. A previous publish attempt failed because the app-owned preview had locked its binaries; closing that preview resolved the failure.

The portable package contains the complete runtime folder and Claude bridge. It is not a single-file app. The packaging script checks required files, rejects common personal/debug artifacts, scans TokenFish binaries for the checkout path, verifies ZIP entry counts, and writes per-file and archive SHA-256 checksums. It creates fresh staging directories instead of deleting existing output. The GitHub workflow has been authored but has not run remotely.

## Desktop validation and remaining gates

The published candidate launched with isolated app settings and both providers. Native Windows Codex reported ready/live quota; Claude's older local observation was visibly labeled stale. Settings' Connections, Desktop, and Appearance layouts were inspected. The widget displayed fish, separate provider values, and stale labeling. The first inspection reproduced a white native widget rim and prompted a further frame fix.

The complete-client-area fix removed the visible white rim from the published widget at the current display scale. Clicking its usage area opened the full view above it. The full view showed both reported Claude windows and expanded Codex summaries/chart; after the expansion transition settled, all labels and values were readable and the footer remained visible. Opening Settings from the full view positioned it to the left with the expected gap. No historical desktop pass is treated as proof for this redesign.

Inspection used `--inspect-windows`, which exposes the normally hidden tool windows to desktop inspection tools without changing their client rendering. Test settings were isolated through TOKENFISH_SETTINGS_PATH; provider authentication and existing Claude observations were not changed. Packaging was tested against synthetic directories containing debug symbols or provider state and correctly refused them.

Live appearance switching to Light was verified in Settings and the widget. Widget hide/restore through Settings was verified while the full view remained available, and both choices persisted. The grip's native move/snap invocation saved its monitor anchor; left/right arrow keys moved between bottom corners and persisted the new corner and anchor. Long pointer drags across displays remain a manual check because the inspection tool did not reliably target the grip during drag strokes. Closing test previews used process cleanup, so this pass does not claim a new manual tray-exit test.

After restoring the mouth animation, successive screenshots of the published widget and full view showed both open and closed mouths for Codex and Claude. Hiding and reopening the full view resumed the animation. Automated cases cover the reduced-motion, hidden, and unloaded eligibility decisions; live switching of the Windows animation setting remains a manual check.
